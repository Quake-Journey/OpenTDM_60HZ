# OpenTDM 60 Гц (r6010): установка, обновление и откат

Инструкция для администратора сервера Quake II под Windows. Исходники, документация и новые выпуски: https://github.com/Quake-Journey/OpenTDM_60HZ

## 1. Что это и что нужно

Это выделенный сервер Quake II для дуэлей 1 на 1 с частотой мира 60 Гц: движок Q2PRO (`q2proded64.exe`) и мод OpenTDM (`opentdm\gamex86_64.dll`). Стрельба, снаряды, рокетджамп, урон от падения и таймеры работают как на обычном сервере 10 Гц, а движение у клиентов с поддержкой 60 Гц плавное. Подробно — в `OpenTDM_60HZ\TRANSITION-RU.txt` архива (в репозитории — `docs/transition-10-to-60hz.md`).

Нужно:

- Windows x64 (Windows 10, 11 или Windows Server 64 бит);
- данные игры Quake II: файлы `pak*.pak` из папки `baseq2` вашей копии Quake II — `pak0.pak`, а также `pak1.pak` и `pak2.pak` из официальных обновлений (карты `q2dm1`–`q2dm8` лежат в `pak1.pak`). Игровые данные в архив не входят и не распространяются;
- свободный порт UDP (обычно 27910) и, если сервер должен быть виден из интернета, проброс этого порта.

## 2. Состав архива

```
q2proded64.exe                        сервер (движок Q2PRO), 64 бит
opentdm\gamex86_64.dll                мод OpenTDM, 64 бит
opentdm\opentdm-60hz.example.cfg      пример настроек дуэльного сервера
OpenTDM_60HZ\README-RU.txt            эта инструкция
OpenTDM_60HZ\TRANSITION-RU.txt        что меняется при переходе с 10 на 60 Гц
OpenTDM_60HZ\KNOWN-ISSUES-RU.txt      известные проблемы и непроверенное
OpenTDM_60HZ\SOURCES-RU.txt           исходники, авторы, лицензии
OpenTDM_60HZ\licenses\                тексты лицензий
OpenTDM_60HZ\SHA256SUMS.txt           контрольные суммы файлов архива
```

Сервер 64-битный и загружает только `opentdm\gamex86_64.dll`. Старый 32-битный сервер (`q2proded.exe`) этот файл не загрузит — он ищет `gamex86.dll`.

## 3. Новая установка и первый запуск на q2dm1

1. Создайте папку сервера, например `C:\q2server`, и скопируйте в `C:\q2server\baseq2` файлы `pak*.pak` из папки `baseq2` вашей копии Quake II.
2. Распакуйте архив в эту же папку. Должно получиться:
   ```
   C:\q2server\q2proded64.exe
   C:\q2server\baseq2\pak0.pak
   C:\q2server\baseq2\pak1.pak
   C:\q2server\baseq2\pak2.pak
   C:\q2server\opentdm\gamex86_64.dll
   C:\q2server\opentdm\opentdm-60hz.example.cfg
   ```
   Если сервер пишет `Couldn't load maps/q2dm1.bsp`, значит, в `baseq2` нет `pak1.pak`.
3. Скопируйте `opentdm\opentdm-60hz.example.cfg` в `opentdm\server.cfg`. В `server.cfg` поменяйте имя сервера (`hostname`) и задайте свои пароли (`rcon_password`, при необходимости `sv_password` и `sv_mvd_password`). Пустой `rcon_password` выключает удалённое управление.
4. Запустите сервер из командной строки в этой папке:
   ```
   cd /d C:\q2server
   q2proded64.exe +set game opentdm +set net_port 27910 +exec server.cfg
   ```
   Сервер всегда ищет `baseq2` и `opentdm` рядом с `q2proded64.exe`. При первом запуске Windows может спросить, разрешить ли программе доступ к сети: разрешите, иначе игроки из сети не подключатся.
5. Проверьте в консоли сервера:
   ```
   sv_fps
   status
   ```
   Команда `sv_fps` должна показать значение 60, `status` — карту `q2dm1`. Команда `version` покажет версию движка `r6010~60hz.187fcd9`.
6. Подключитесь клиентом: `connect <адрес сервера>:27910`.

Остановить сервер — команда `quit` в его консоли.

Чтобы сервер был виден в списках серверов, поставьте в `server.cfg` `set public "1"` и добавьте строку `setmaster` с адресом мастер-сервера.

## 4. Настройки, на которые стоит посмотреть

Все строки примера снабжены пояснениями. Главное:

- `sv_fps "60"` — частота мира. Допустимы 10, 20, 30, 40, 50, 60. Любое другое значение (например, 25) мод OpenTDM не принимает: сервер останавливается с ошибкой `sv_fps must be 10, 20, 30, 40, 50 or 60`.
- `set sv_allow_timers "1" s` — разрешает клиенту Q2PRO-X самому показывать таймеры подобранных предметов; `"0"` — запрещает.
- `sv_mvd_autorecord_matches "1"` — автозапись каждого матча в `opentdm\demos`. Если раньше демки писались по смене карты через `alias`/`trigger` в конфиге, такие строки уберите: при включённой автозаписи ручные `mvdrecord`/`mvdstop` отклоняются.
- `sys_timerperiod "1"`, `sys_nothrottle "1"` — нужны для ровных шагов 16,7 мс под Windows (оба включены по умолчанию; не выключайте).
- Значения переменных, помеченных флагом `s` (видны в информации о сервере), должны быть короче 64 символов — более длинные движок отклоняет с сообщением `Info cvars should be less than 64 characters long`.

## 5. Обновление работающего сервера

Если у вас уже работает сервер Quake II на 10 Гц:

1. Остановите сервер.
2. Сохраните копию того, что будете менять, в отдельную папку, например `C:\q2server\backup-before-60hz`:
   - ваш конфиг сервера (например, `opentdm\server.cfg`);
   - `opentdm\gamex86_64.dll`, если он у вас уже был;
   - `q2proded64.exe`, если он у вас уже был.
   Старый 32-битный сервер (`q2proded.exe` и `opentdm\gamex86.dll`) архив не затрагивает — эти файлы можно оставить на месте для отката.
3. Скопируйте из архива `q2proded64.exe` и `opentdm\gamex86_64.dll` в папку сервера (с заменой).
4. В своём конфиге:
   - поставьте `set sv_fps "60"`;
   - перенесите из примера строки `sys_timerperiod`, `sys_nothrottle`, `sv_tickdiag`, `sv_packetdup_hack`, `sv_allow_timers`, а также `sv_mvd_enable`, `sv_mvd_autorecord_matches`, `sv_mvd_autorecord` и `sv_mvd_spawn_dummy` (блоки «частота мира» и «демки MVD»);
   - уберите прежнюю запись демок по смене карты, если она была;
   - пароли, имя сервера, адрес и порт оставьте свои.
   Если в вашем конфиге есть настройки другой сборки OpenTDM, которых в этом моде нет, сервер просто запомнит их как переменные без действия; на игру они не влияют.
5. Запускайте теперь `q2proded64.exe` (а не прежний `q2proded.exe`) с теми же параметрами командной строки, что и раньше, например:
   ```
   q2proded64.exe +set game opentdm +set net_port 27910 +exec server.cfg
   ```
6. Проверьте `sv_fps` и `status`, как в разделе 3.

## 6. Откат

1. Остановите сервер.
2. Верните сохранённые файлы из папки резервной копии (конфиг, `opentdm\gamex86_64.dll` и `q2proded64.exe`, если они у вас были до обновления).
3. Если до обновления вы запускали 32-битный `q2proded.exe`, просто запускайте его снова со своим прежним конфигом: архив его файлы не менял.
4. Проверьте: команда `version` больше не показывает `r6010~60hz`, `sv_fps` — прежний.

Демки, записанные сервером 60 Гц, остаются в `opentdm\demos` и откатом не удаляются.

## 7. Что заметят игроки

- Клиенты с поддержкой точной частоты (Q2PRO-X с включённой адаптацией, клиенты на основе q2trek/q2pro) получают 60 снимков в секунду: движение, лифты и полёт снарядов плавные.
- Остальные клиенты получают 10 (или 20) снимков в секунду и видят игру как на обычном сервере (в сети проверен Q2PRO-X без адаптации; другие старые клиенты не проверялись).
- Стрельба, рокетджамп, урон и таймеры предметов — как на обычном сервере 10 Гц.
- Лифты и двери трогаются и доезжают немного раньше, чем на 10 Гц (до 0,17 с; дверь открывается до 0,25 с раньше).
- Игроки могут включить повтор пакетов командой `packetdup 1`..`packetdup 3` (на случай потерь).

Известные проблемы: файл `OpenTDM_60HZ\KNOWN-ISSUES-RU.txt`.

## 8. Проверка файлов

Контрольные суммы SHA-256 файлов архива — в `OpenTDM_60HZ\SHA256SUMS.txt`. Проверить файл в PowerShell:

```
Get-FileHash .\q2proded64.exe -Algorithm SHA256
Get-FileHash .\opentdm\gamex86_64.dll -Algorithm SHA256
```

Ожидаемые значения для r6010:

```
afbc3305e69bed7c8187af697b5e3c737983591fc6510a0c03dc12b24f03de26  q2proded64.exe
8c6ab27def6a6a246514d53f8f4cccf6f83f8042b9423a218bdcbd2d099921f9  opentdm/gamex86_64.dll
```
